# Ozon 大学知识对 ozon-workbench 的产品建议

## 结论

项目不应变成“所有 Ozon API 的按钮集合”。它应成为 FBO 卖家的本地经营与财务控制台。

## 北极星能力

### 1. 数据可信

- 店铺隔离；
- 增量同步可续跑；
- 分页完整性；
- 原始事实可追溯；
- 接口版本和字段契约；
- 数据更新时间和覆盖范围可见。

### 2. FBO 闭环

`商品 → 供应 → 入仓 → 库存 → 订单 → 退货 → 财务 → 结算`

任何指标都应能下钻到这条链上的证据。

### 3. 可解释利润

- 订单收入；
- SKU 成本；
- 佣金；
- FBO 履约和物流；
- 仓储；
- 推广；
- 退货；
- 补偿和无订单费用。

既展示原始归属，也可做明确标注的管理分摊。

## 推荐产品模块

### P0：先修底座

- 端点注册表和契约测试；
- 旧类目接口迁移；
- 统一限流与重试；
- 取消静默 50 页截断；
- 同步状态、覆盖区间和失败解释；
- UTF-8 编码治理。

### P1：FBO 经营核心

- SKU 主数据与标识映射；
- FBO 供应/入仓差异；
- Ozon 仓 × SKU 库存；
- 补货与长仓风险；
- 退货生命周期；
- SKU 贡献毛利；
- 结算周期闭环。

### P2：增长

- 商品健康度；
- 搜索漏斗；
- 活动毛利模拟；
- 广告净贡献；
- 评价主题与问题诊断；
- 经营实验记录。

### 不做

- FBS、rFBS、FBP 履约；
- FBS 仓库和库存写入；
- 自动发货或取消；
- 无审批自动改价和参加活动；
- 自动发送客服、问答或评价回复；
- 把银行到账伪装成平台利润，或反之。

## 建议的新页面

1. **数据健康中心**：权限、同步、覆盖、完整性、版本。
2. **FBO 供应中心**：供应单、货件、入仓、差异。
3. **库存与补货**：仓库分布、在途、可售天数、建议补货。
4. **SKU 利润中心**：真实费用、退货后贡献、活动模拟。
5. **售后洞察**：退货、评价、质量主题和批次风险。
6. **规则与任务**：告警、证据、负责人、关闭条件。

## 数据模型建议

核心表：

- `shops`
- `products`
- `product_identifiers`
- `fbo_postings`
- `fbo_supply_orders`
- `fbo_cargoes`
- `fbo_inventory_snapshots`
- `returns`
- `finance_operations`
- `finance_operation_services`
- `cashflow_statements`
- `report_artifacts`
- `sync_runs`
- `api_endpoint_contracts`
- `alerts`
- `experiments`

## 成功标准

- 用户能判断数据是否完整；
- 每个重要数字能下钻到事实；
- 每个结算差异有原因；
- 每个补货建议有计算依据；
- 每个促销建议包含利润和库存影响；
- FBS/rFBS/FBP 不污染 FBO 决策。

## 2026-07-30 新增的 P0 兼容任务

### FBO posting 接口迁移

当前后端仍使用 `/v2/posting/fbo/list`。Ozon 已公告该方法将在 2026-08-31 停用，必须迁移到 `/v3/posting/fbo/list`。

验收标准：

- v3 客户端、分页和错误处理独立实现；
- 保存 v2 与 v3 的脱敏响应契约；
- 同窗双读比较 posting、SKU 数量、状态和金额；
- 验证日期边界与取消单口径；
- 切换后仍可从同步运行记录看到接口版本；
- 在停用日前移除生产环境的 v2 依赖。

### FBO 供应模型改为集群优先

- 跨仓供应以 `macrolocal_cluster_id` 为业务目标；
- 直接供应仍可使用仓库维度；
- 时隙必须注明绑定集群还是仓库；
- 供应路线、运输货件和验收差异必须独立建模；
- 不使用恒为空的 `storage_warehouse.arrival_date` 生成到仓预测。
