# Ozon 财务、费用、结算与对账蒸馏

## 1. 三种口径不能混

- **经营利润**：销售收入减商品成本和全部经营费用。
- **平台结算**：Ozon 按结算规则计算应付或扣款。
- **银行到账**：真正打入银行的现金。

三者时间和金额都可能不同。

## 2. 事实源分工

- 订单：卖了什么、什么时候发生。
- 财务流水：产生了哪些计提、扣款、退款和补偿。
- 现金流/账单：平台结算周期内如何汇总和支付。
- 异步报告：更细的仓储、供应、商品或费用明细。
- 银行流水：最终实收。

单一接口无法完成完整对账。

## 3. 费用分类

建议统一到本地科目：

- 商品销售；
- 销售佣金；
- FBO 履约与配送；
- 仓储；
- 供应和入仓服务；
- 退货物流；
- 推广、订阅和活动；
- 补偿、赔付和调整；
- 罚款或其他扣款；
- 税费；
- 未分类。

保存平台原始操作类型和本地科目映射版本，避免规则变化后无法重算。

## 4. 关联原则

优先级：

1. 平台直接给出的 posting/operation/SKU；
2. 明确的服务费子项；
3. 报表内的商品或供应关联；
4. 只能按周期归集的无订单费用。

不要为了“每单利润”好看而把订阅、广告、仓储等费用强行分摊到订单。可以提供分析性分摊，但必须和原始会计归属分开。

## 5. 退货的财务链

一笔退货可能出现：

- 原销售计提；
- 原佣金冲回或调整；
- 买家退款；
- 正向和逆向物流费；
- 商品回仓；
- 报损；
- 平台补偿；
- 跨结算周期调整。

所以“退款金额”不等于“这笔订单最终损失”。

## 6. 对账闭环

每个结算周期应回答：

- 期内平台账单金额；
- 同期已拉取财务操作总额；
- 无订单费用；
- 退款、补偿和调整；
- 银行是否到账；
- 差异属于时间、缺数、重复、映射还是未知；
- 是否达到可关闭条件。

只有差异为零，或每一笔差异都有明确、可追踪原因，才能关闭周期。

## 7. 数据工程规则

- 原始流水不可覆盖，使用平台唯一键幂等写入。
- 重复同步同一周期不能累计重复账单。
- 时间窗口允许重叠，通过唯一键去重。
- 保存同步覆盖区间和完整性。
- 报表文件保存参数、生成时间、校验值和解析版本。
- totals 只能用于交叉校验，不能替代明细。

## 8. FBO 专项分析

项目需要回答：

- 每个 SKU 的净销售与贡献毛利；
- 每单履约和退货成本；
- 仓储费从哪些 SKU、仓库和库存龄产生；
- 入仓差异是否产生补偿；
- 促销后销量增长是否覆盖利润下降；
- 哪些费用无法关联订单；
- 哪些结算周期仍未闭环。

## 9. 当前项目评价

现有项目已具备：

- `/v3/finance/transaction/list` 流水；
- totals 校验；
- 现金流账单；
- 服务费子项拆分；
- 结算周期去重；
- 无订单费用池；
- 差异下钻。

下一步不是再做一张汇总表，而是提高覆盖完整性、费用映射版本化和 FBO 仓储/供应费用解释能力。

## 12. 对项目的直接影响

- 当前“平台财务流水”不能替代销售报告、付款报告或往来对账单。
- 补偿与撤销补偿应作为成对但独立的财务事实保存，不能净额覆盖原记录。
- 按订单销售报告适合订单级校验；商品销售报告适合期间与商品口径；两者用途不同。
- B2B 预付款和普通预付款必须区分，避免税务和结算口径混合。
- 卖家欠款和延迟支付需要单独状态，不能简单显示为“未到账”。
- 税制属于主体级配置，不应从交易流水自动猜测。

## 13. 官方页面级核验：卖家付款

> 核验页面：`/libra/finances-documents/calculations-documents/payments`
>
> 核验日期：2026-07-30。付款日期、产品和服务属于动态规则，使用时需重新核对。

官方付款口径：

- 付款＝商品销售收入减去平台佣金和各类服务费用。
- 只有余额为正时才会形成付款。
- 结算周期是一整周：周一至周日。
- 标准计划为每周三付款，并延后三周。
- 银行还可能继续处理最多 2 个工作日。
- 灵活计划可通过相关服务改为下一周、延后一周/两周，或工作日每日付款。
- 还存在按需提前付款，以及额外延迟 14–168 天以换取销售佣金下降的方案。
- 一个结算周跨越月末时，Ozon 会拆成两笔付款，分别对应两个自然月。
- 没有销售的结算周期不会生成付款单；恢复销售后按后续周期处理。

付款状态：

- `等待付款`：付款单已准备，但交易尚未得到银行确认、被银行拒绝或日期未到；
- `已付款`：款项已进入卖家账户；
- `已取消`：Ozon 未能发送付款。

核对依据：

- 后台“计提明细”等页面与实际付款可能不同，例如买家使用积分或分期。
- 官方页面要求以商品销售报告作为核对依据。
- 商品销售报告通常在次月前 5 个工作日提供，最迟不晚于 8 日。
- 付款资料变更从下一个结算周期开始生效。

官方人工月度核对链：

1. 商品销售报告：销售和退货，含合作伙伴忠诚度补贴；
2. 销售报告对应的 УПД-1：Ozon 销售佣金；
3. 服务转付报告：合作伙伴执行的服务；
4. 卖家服务执行单：Ozon 提供的服务；
5. 往来结算报告：补偿和其他计提；
6. 付款报告：保持报告中的正负号；
7. realFBS 合作伙伴配送付款（项目不采用，但知识保留）；
8. 积分结算奖励单；
9. 特殊商品服务执行单；
10. 将结果与“财务 → 付款”的实际付款逐笔比较。

项目映射：

- 结算周期模型必须明确使用周一至周日，并允许跨月拆成两笔银行付款。
- `payment_status` 不能只用已到账/未到账二值，应保存等待、已付、已取消及银行处理状态。
- 付款、财务流水、现金流账单、销售报告必须作为四种不同事实源保存。
- 销售报告应成为月度核对的权威输入之一；后台计提明细不能单独作为签收依据。
- 折扣积分、分期、补偿、转付服务、Ozon 服务和特殊服务必须分别入账。
- 结算差异应能够追踪到上述官方人工核对链的具体单据。

## 14. 官方页面级核验：后台财务功能

> 核验页面：`/libra/finances-documents/calculations-documents/work-with-finance`
>
> 核验日期：2026-07-30

后台财务信息架构：

- 余额：收入与支出、余额历史、平台收购商品、欠款；
- 店铺经济：计提明细、单品经济、折扣积分；
- 付款；
- 单据；
- 服务、仓储费用、保险、公益、业务发展和银行。

余额字段：

- 当前余额；
- 已预留：为未来付款、贷款或保理扣款预留；
- 月初余额；
- 本月计提：收入减全部支出；
- 本月已付款。

重要边界：

- “平台收购商品”的余额与普通余额不相加，应作为独立事实域。
- 平台收购使用 УПД，退回使用更正单据；只有签署 УПД 后金额才进入余额。
- 原创品牌保证金有独立余额、扣款、返还和罚款历史。
- 余额充值通常需要 3–7 个工作日，不能把充值申请时间当作到账时间。

计提明细：

- 可查询 2022-01-01 至今，但单次期间不超过 31 个自然日。
- 可按销售、退货、配送、推广等类型筛选。
- 销售和退货会拆分商品销售、折扣积分和合作伙伴忠诚度。
- 正计提与负计提分别展示；总计＝销售退货＋负计提＋正计提，并纳入期初欠款。
- 可按计提 ID、posting 编号、货件 ID 或订阅周期精确搜索；精确搜索不受页面日期/类型筛选限制。
- 一个 posting 多商品时可下钻到商品；同货号多件可能合并显示。
- 后付款订单的收单费用按 posting 编号而不是订单编号显示。
- 可下载计提报告和物流报告；页面核验时物流报告仅覆盖 2026-04-06 之后产生物流费用的销售。

项目映射：

- 现有 API 的 28 天时间切片符合“不超过 31 天”的限制，但应把该限制写入端点契约而不是藏在代码注释中。
- `balance_reserved`、期初余额、当期计提、已付款和欠款必须分字段保存。
- 平台收购、保证金、余额充值不能混入普通销售结算。
- 计提搜索键应包括 `operation_id/posting_number/cargo_id/subscription_period`。
- 物流报告有数据起始日期，UI 必须显示覆盖范围，历史为空不能解释为没有物流费。
- 正负计提应保留原始符号，禁止先取绝对值再分类。

## 15. 官方页面级核验：卖家欠款

> 核验页面：`/libra/finances-documents/calculations-documents/zadolzhennost`
>
> 核验日期：2026-07-30。付款期限、税率、银行资料、推广解锁阈值和合同后果均属动态规则，执行前必须重新核对。

欠款形成与固化：

- 欠款是卖家应付给 Ozon 的金额，常见原因是收入低于服务费与退货计提，或 Ozon 以前期间多付。
- 月内临时负余额不等于已固化欠款；Ozon 按自然月最后一天的最终余额判断。月末仍为负数才固化为欠款并开账单。
- 欠款金额可在“财务 → 余额”的当前余额和警示横幅查看；账单在次月 10 日前进入“财务 → 单据 → 付款账单”，并通过 EDI 发送副本。
- 已开账单须从开出之日起 7 个自然日内全额支付。即使当前余额后来转正，原账单仍应按期全额支付；后续正余额会在结算中自动重算。

支付与确认：

- 官方列出的偿债方式包括后台或应用充值、从结算账户转账、协商抵销。
- 页面核验时标示偿债付款使用 22% VAT，且列出的银行资料仅适用于俄罗斯卖家；这两项必须视为动态财税信息。
- 第三方个人或组织代付时，付款用途需包含被代付主体、合同号与依据、账单编号和日期。
- 无需主动提交回执，但应保存至款项出现在“收入与支出 → 其他计提 → 本期入账”且当前余额已调整。
- 横幅消失与付款到账可能不同步；官方说明在月底前清偿后，通常于次月 10 日后消失。

业务限制与风险：

- 月末固化欠款会暂停灵活付款计划和提前付款；收款且余额转正、仍满足服务条件后恢复。
- 付费推广实行即时自动控制：一出现欠款即可暂停商品推广和展示广告，既有活动变为非活动且不能新建。
- 页面核验时，推广自动恢复条件为当前余额至少正 5,000 卢布，满足后 24 小时内恢复；活动仍需手动重启。阈值属于动态规则。
- 同一法人有多个后台时，同时看单后台余额和全部后台余额合计：合计为正时只限制欠款后台；合计为负时可限制全部后台。
- 未偿债时，合同允许 Ozon 以卖家承担的折扣促销偿债，或单方解约并诉讼；具体执行必须回到最新合同核对。

FBO 与项目映射：

- FBO 仓储费、推广费、错误商品尺寸引起的更高物流费和复测费都是欠款风险源，利润预警不能只看销售佣金。
- 增加 `month_end_debt`、`invoice_issued_at`、`invoice_due_at`、`debt_paid_at`、`banner_cleared_at`，区分临时负余额、固化欠款、账单和 UI 状态。
- 欠款状态应驱动风险提示，但不能在本地系统中擅自推断 Ozon 已封禁或已恢复；平台状态需要官方事实源确认。
- 多店铺应按法人主体聚合余额，同时保留店铺级欠款，避免只看单店得出错误推广可用性。

## 16. 官方页面级核验：销售款延迟支付

> 核验页面：`/libra/finances-documents/calculations-documents/otsrochka-platezha`
>
> 核验日期：2026-07-30。可选天数、佣金折扣、最低佣金及服务资格属于动态商业条款。

机制与周期：

- 延迟支付允许把销售所得再推迟 14–168 天，以换取销售佣金降低。
- 它作用于完整结算周（周一至周日）的全部付款类型，包括销售收入、补偿和重算。
- 开通、期限调整或关闭都从下一个结算周期，即最近的周一起生效。
- 延迟是在原付款计划日期基础上叠加；计划日期落在非工作日时，转到最近工作日。
- 不关闭会自动延续。首笔形成时间差后，后续仍按周收到更早结算周的款项，不等于付款频率永久降低。

资格、组合限制与退出：

- 页面核验时仅面向在俄罗斯注册且以卢布收款的卖家。
- 不能与灵活付款计划组合。
- 可以申请提前付款，但提前付款费率会提高，可能抵消延迟支付带来的佣金节省；精确费率以开通页面为准。
- 延迟期间 Ozon Credit 和“销售前资金”贷款的销售款自动偿还会停用，卖家必须自行保持银行扣款账户余额或按贷款银行资料付款。
- 要阻止下一周继续延迟，必须在当前结算周结束（周日）前关闭；本周仍按既定延迟执行，下一周恢复标准计划。

计费与退货：

- 佣金折扣从延迟服务生效的订单周期计算；若叠加折扣后佣金为零或负数，页面说明仍会收取最低允许金额。
- 退货按下单时有效的销售佣金规则计算，即便退货发生时延迟期已经结束。
- 计划付款日期应直接读取“财务 → 付款”的官方日期，不能仅以本地公式预测。

项目映射：

- 将 `base_payout_date`、`defer_days`、`planned_payout_date`、`actual_payout_date` 和 `payout_schedule_type` 分开保存。
- 佣金必须带生效周期与规则版本；退货重算引用原订单时点版本，不能套用当前费率。
- 现金流预测需要同时反映延迟回款与佣金下降；经营利润和现金可用性是两个独立指标。
- 借款自动还款在延迟期间中断，应产生资金风险提醒，但项目不得代替银行/Ozon 判断是否逾期。

## 17. 官方页面级核验：支付与财务问答

> 核验页面：`/libra/finances-documents/calculations-documents/vopros-otvet-finansy`
>
> 核验日期：2026-07-30。此问答页与同栏目的专题正文存在部分数字冲突，不能把 FAQ 单独作为动态规则的唯一依据。

### 页面间冲突与采用原则

- FAQ 仍写标准付款每月两次，而“卖家付款”专题正文写完整周结算、每周三且延后三周。
- FAQ 一处写延迟支付 15–90 天，后文及“销售款延迟支付”专题正文写 14–168 天。
- 同一 FAQ 说银行处理可能额外 2 个工作日，也说计划日后最多 3 个工作日。
- 因此项目不得把这些数字硬编码；以更具体的专题正文、卖家后台实际计划付款日期和当前合同为优先事实源，并记录核验日期。

### 付款与核对

- 付款只在余额为正时发生；计划付款、历史付款和状态位于“财务 → 付款”。
- FAQ 增加了“形成中”状态：账单正在生成；“等待付款”既可能是日期未到、银行未确认或银行拒绝；“已付款”仍需和银行到账核对。
- 即使银行已到账，平台也可能因等待银行确认暂时显示“等待付款”；平台状态和银行现金事实必须分开。
- 历史月份可用往来结算报告做汇总核对，或用全部关账单据做详细核对；仅适合相应标准付款计划。
- 在线计算器可能没有最新佣金和费率。当前费用应优先看商品列表中相应履约模式的费用列及具体类目佣金，并用 XLSX 计算器辅助。

### 折扣积分与忠诚度

- 页面说明商品每优惠 1 卢布可产生等值 1 卢布的平台服务折扣积分，可用于销售佣金、物流、仓储、推广等服务。
- 积分在月结后冲抵，页面核验时最高可覆盖当月佣金与服务总成本的 99%；比例属于动态规则。
- 合作伙伴忠诚度补贴是合作伙伴弥补买家优惠差额，Ozon 作为资金转付代理。
- 销售收入和合作伙伴忠诚度补贴都需进入收入核算；页面说明二者均涉及 VAT，但具体税务处理必须由会计按主体和当前法规确认。
- 忠诚度补贴可能来自不同法人，必须保存付款方/纳税人识别信息，不能全部归为 Ozon 自有补贴。

### 订单状态与计提时点

- 商品收入、销售佣金和配送费在订单进入“已送达”时计提；收单费在订单付款时计提。
- 退货、取消和未取件的收单费退回、商品收入冲回及销售佣金返还，在 Ozon 收到对应退回事件时发生。
- 退回处理费和逆向物流在商品回到 Ozon 仓库时计提（FBO）；FBS 的触发条件不同，仅保留为知识，不映射到当前项目能力。
- 同一订单的各项计提天然可能跨时间发生，不能用“订单号 + 日期”假设只有一条财务记录。

### 主体与收款资料

- 账号不能改挂到另一个法人或个体工商户，纳税人识别号也不能修改；需要新建后台，商品卡可申请付费迁移。
- 页面核验时，仅“管理者”角色可自助修改部分银行和地址资料，且不超过每两周一次；其他资料需支持介入。
- 新收款资料从下一结算周期开始生效，因此资料变更日和首次使用新资料的付款周期必须分别记录。

### 费率版本与营销服务

- 销售佣金和服务费通常按下单日有效规则计算；但退货、取消或未取件可能按事件发生时的新规则计算。
- 广告费用会按是否属于网络广告标记义务拆分成网络广告、其他广告、其他营销与技术服务等行，不能按中文显示名粗暴合并。
- 费用事实应保存 `rule_effective_at`、`order_created_at`、`event_occurred_at` 和原始服务名称，支持解释跨版本差异。

### 项目映射

- 扩展付款状态为 `forming / awaiting_payment / paid / cancelled`，并单独保存银行到账状态和银行确认时间。
- 本地预测日期只作预测；官方计划日期、平台状态、银行到账分别建模。
- 财务明细必须支持一个 posting 多个事件时点、多条服务费和不同费率版本。
- 折扣积分、合作伙伴忠诚度补贴、广告服务分类必须保留独立原始科目及付款主体。
- 建立“官方页面冲突”规则：检测到同域数字不一致时标记 `source_conflict`，禁止自动把任一数字升级为系统常量。

- 页面核验时，2025-12-25 后 FBO/FBS 公式为：`补偿额 = 实际价值 × 补偿系数 ÷ (1 + VAT 税率)`。

- VAT 税率来自商品卡或特殊供货 УПД；Ozon 可要求价值证明，页面给出的提交期限为 5 个工作日。
- realFBS 使用声明价值公式，仅作知识保留，当前项目不实现。

项目映射：

- 补偿必须作为正向独立事实保存，字段包括 `compensation_type`、`quantity`、`actual_unit_value`、`gross_value`、`reduction_amount`、`compensation_amount`。
- 保存 `valuation_basis`、价格观察窗口、VAT 来源、补偿系数和规则版本，才能解释为什么补偿不等于零售价。

## 23. 官方页面级核验：撤销补偿报告

> 核验页面：`/libra/finances-documents/documents/otchet-o-dekompensaciyah`
>
> 核验日期：2026-07-30。汇率和合同币种属于动态金融信息。

撤销补偿机制：

- 撤销补偿是收回以前已经支付的补偿。若曾获补偿的商品后来被找到且商品卡仍处于激活状态，Ozon 将其作为库存盈余重新销售，并扣回原补偿。
- 若卖家已不再销售该商品，官方建议先将商品卡归档；否则找到商品时仍可能产生盈余和撤销补偿。
- 报告是月度关账单据，次月前 5 个工作日形成且不晚于 8 日，并上传后台及 EDI。

成对关联与金额：

- 报告明确包含原补偿单据编号和日期，撤销补偿必须与原补偿一一追溯，不能仅按 SKU 和金额猜测。
- 其他字段包括商品、卖家货号、SKU、条码、数量、单位实际价值、实际价值总额、调整金额和最终应扣金额。
- 最终应扣金额＝实际价值总额－调整金额；月度“总扣回”汇总所有撤销补偿。
- 官方说明扣回金额应与此前实际补偿金额完全相同；此前计算中已考虑销售佣金、物流/最后一公里和 VAT。

币种变化：

- 若原补偿时合同为卢布、撤销时已改为其他币种，页面说明按撤销发生日的俄罗斯央行当前汇率换算。
- 因此“原币金额相同”与“本币账面金额相同”不是一回事，必须保存原币、目标币、汇率日期和汇率。

项目映射：

- 使用 `original_compensation_document_id/date` 建立强关联，撤销记录不得覆盖原补偿。
- 增加库存事件链：`lost/damaged → compensated → found → surplus → returned_to_sale → decompensated`。
- 补偿和撤销补偿在损益中可净额分析，但原始会计事实必须成对保留。
- 商品卡归档状态会影响是否产生撤销补偿，应作为风险提示输入，但不能由项目自动替卖家归档。
- 跨币种扣回保存 `source_currency`、`target_currency`、`fx_rate_date`、`fx_rate` 和双方金额。

## 24. 官方页面级核验：转付报告

> 核验页面：`/libra/finances-documents/documents/otchet-o-perechisleniyah`
>
> 核验日期：2026-07-30。此处“转付”不是银行向卖家支付销售款的流水，而是特定配送、买家补偿和扣款的月度单据。

报告范围：

- 月末形成两类报告：通用转付报告，以及 realFBS 伙伴配送专用报告；后者仅保留知识，当前 FBO 项目不实现。

- 此报告不是银行到账来源，命名应避免翻译成普通“付款报告”。
- FBO 只吸收适用的退还配送费、退货配送补偿和买家部分补偿；FBS/realFBS 少件与配送操作仅存知识标签。
- 保存 `posting_number`、`accrual_date`、`accrual_type`、各组成金额和官方原始符号。
- 同一货件可有多种相反方向的计提，禁止按货件先净额化后入库。

## 26. 官方页面级核验：商品预付款报告

> 核验页面：`/libra/finances-documents/documents/otchet-po-predoplatam`
>
> 核验日期：2026-07-30。VAT 税率、公式和抵扣期限属于动态税务信息，不能由项目替代会计判断。

报告性质：

- 这是参考报告，不是付款依据；Ozon 只对已经实现销售的商品形成卖家付款，预付款报告金额不进入最近一次卖家付款计算。
- 报告用于跟踪买家预付款，并辅助处理预付款 VAT。
- 它分别记录预付款收到、买家取得商品形成销售、买家未取得商品而退回预付款三个阶段。

- 收到预付款、实现销售和退回预付款可能跨月，必须作为三个事件分别保存。
- “退回预付款”表示未完成销售时退回预收款，不等同于商品交付后的客户退货。

项目映射：

- 建模为 `prepayment_received → realized` 或 `prepayment_received → prepayment_refunded` 两条路径。
- 保存 `prepayment_period/amount`、`realization_period/amount`、`refund_period/amount`，禁止把报告余额直接当收入或应收款。
- 预付款报告与销售报告通过商品、期间和可用业务标识关联，但不能互相覆盖。
- VAT 计算仅提供辅助字段和来源链接；税率、应计、抵扣与期限必须交给会计配置或外部税务系统。

## 28. 官方页面级核验：往来结算对账单

> 核验页面：`/libra/finances-documents/documents/act-sverki`
>
> 核验日期：2026-07-30。合同条款、回复期限和单据分类属于动态规则。

季度与自选期间：

- 对账单汇总 Ozon 与卖家整个季度的往来，不是强制单据；只有双方签署后才具有相应法律效力。
- Ozon 在每季度结束后、次月 15 日前形成季度对账单，后台保留自合作开始以来的季度单据。
- 卖家可自行生成 1–12 个已关闭月份的自选期间对账单，页面核验时最早从 2023-01 起。
- 自选对账单通常一小时内形成，仅显示 7 天，无 Ozon 签章且无需接受或拒绝，仅供查看；支持只处理正式季度对账单争议。

借贷与余额：

- 单据按时间列出文件编号、日期、类型、借方和贷方。
- 借方表示卖家对 Ozon 的债务，贷方表示 Ozon 对卖家的债务。
- 期初余额等于上一期间期末余额；期末余额由期初和本季度全部操作形成。
- 期末余额在借方表示卖家欠 Ozon，在贷方表示 Ozon 欠卖家。
- 卖家账簿与 Ozon 应镜像：Ozon 借方应等于卖家贷方，反之亦然。

接受与争议：

- 页面核验时，卖家收到季度对账单后有 15 个工作日接受或拒绝，未回复将自动接受。
- 拒绝后需提交从合同开始日至对账期末的自有对账单，而不是只提供当前季度。
- 页面说明首次争议通常在 5 个工作日内处理；重复对账的检查期为 3 个工作日，全部协商应在下一季度结束前完成。
- 常见差异原因：Ozon 未提供完整关账单据、卖家漏记单据、同一单据归入不同期间、卖家把多个合同或后台合并到同一对账单。
- 每个合同/后台必须单独对账；确认差异后通过差异协议记录，并在后续对账单体现。

项目映射：

- 保存 `contract_id`、`account_id`、`period_start/end`、期初/期末借贷余额、周转额及每行官方单据引用。
- 对账工作流支持 `received / under_review / accepted / rejected / accepted_with_discrepancies / auto_accepted`。
- 增加法定响应截止日提醒，禁止将“未处理”直接显示成“无差异”。
- 本地对账导出应能覆盖合同开始日至期末，且禁止跨合同净额。

## 29. 官方页面级核验：单据问答

> 核验页面：`/libra/finances-documents/documents/vopros-otvet-documents`
>
> 核验日期：2026-07-30。FAQ 存在旧信息或与专题正文不一致，动态事实以专题正文、实际单据和合同优先。

权威层级：

- 后台页面数据是期间内动态估算，可能省略 Ozon 承担的折扣和加价；月末关账单据才是最终金额事实。
- 无销售且无退货时可能不会形成销售报告；也可能只是尚未到次月第 5 个工作日/8 日期限。
- Ozon 自身服务单据中的 VAT 取决于 Ozon 的税制，不等于卖家的 VAT 税率。
- 伙伴服务不形成对应 УПД；含 VAT 的伙伴服务发票由实际执行者提供，经 Ozon 转送，报告期结束后最晚可延迟 60 天。
- 商品补偿和其他补偿分属不同报告；FAQ 说明补偿可能脱离常规付款计划独立支付，并在次月 15 日前形成付款单。

FAQ 冲突：

- FAQ 仍称每月形成销售报告对应 УПД-1，但专题总览已说明该单据在 2026 年 7/8 月迁移，不能沿用静态描述。
- FAQ 说按订单销售报告位于“关账”标签，而该报告专题正文明确其位于“参考”标签且不是关账单据。
- FAQ 的服务执行单描述未完整反映专题页所述销售佣金迁移。
- 上述冲突全部标记 `source_conflict`，FAQ 只作异常解释入口，不作为 schema 和费率的唯一依据。

其他操作要点：

- 伙伴发票应按实际伙伴信息及 Ozon 代理信息入账；VAT 抵扣权页面核验时保留三年，具体操作交给会计。
- “期间报告”缺少服务或金额异常时，应以关账单据核验，并可从“店铺经济”下载按商品/计提 XLSX。
- 其他补偿若不在商品补偿报告中，会在往来结算报告的“补偿和其他计提/其他计提”中体现。
- 正转付通常是特定配送收入或补偿，负转付为退还配送费、少件或部分买家补偿等支出。
- 争议后新对账单可能只在支持工单中签署而不重新上传后台；后台计时器结束不改变已经在工单中达成的协议。

项目映射：

- 建立事实优先级：签署/关账文件 > 专题正文 > FAQ > 动态后台估算。
- FAQ 发现的异常场景转化为校验和支持工单指引，不直接覆盖财务事实。
- 补偿付款与常规销售付款分开保存，支持不同付款计划和单据日期。
- 对账争议文件允许来自支持工单，并保存其与后台旧对账单的关联。

## 30. 官方页面级核验：选择税制

> 核验页面：`/libra/finances-documents/taxes/nalogi`
>
> 核验日期：2026-07-30。税率、收入门槛、人员/资产限制、申报期限和适用法规高度动态；本节仅记录页面当日内容，不构成税务建议。

适用税制边界：

- 页面列出 ОСНО、УСН、НПД、АУСН、ЕСХН 可用于 Ozon；ПСН 不适用于互联网零售。
- 税制属于卖家法律主体级配置，不由履约模式决定；页面列出的各税制均可覆盖 FBO、FBS 和 realFBS。
- НПД 仅允许销售自产商品，并受雇员和收入等限制；АУСН、УСН、ЕСХН 也各有主体、区域、收入、人员或业务限制。
- 选择税制需要结合主体、成本结构、进项 VAT、B2B 买方需求及业务规模，不能由平台流水自动推断。

页面当日的重要动态数字：

- 页面写 ОСНО 利润税 25%，商品 VAT 通常为 10% 或 22%，视商品类目而定。
- 页面写 2026 年 УСН 年收入超过 2,000 万卢布后涉及 VAT，并列出 5%、7% 或经典 10%/22% 等路径及不同门槛。
- 页面写 НПД 年收入上限 240 万卢布、对自然人销售税率 4%；平台收购用于跨境时可能出现不同处理。
- 页面还列出 УСН、АУСН、ЕСХН 的年度收入、人员和资产阈值；这些数值必须在实际决策前向俄罗斯税务机关和最新法规复核。

平台配置：

- 税制与 VAT 变化需要同时在税务机关完成并更新 Ozon 后台，不能只改本地系统。
- 页面说明 УСН 卖家可在后台更新 VAT 税率；配置变更需要有效日期和证明文件。
- 商品卡/特殊 FBO 供货单据中的 VAT 税率会影响单据和补偿计算，因此主体税制与商品税率是两个层级。

项目映射：

- 使用主体级 `tax_regime_history`，保存税制、有效期、证明文件、核验来源和配置状态。
- 使用商品级 `vat_rate_history`，禁止用主体税制覆盖所有商品。
- 任何阈值判断输出“可能触发复核”，不得自动宣布纳税义务或替卖家切换税制。
- 税制变更需要同时检查 Ozon 后台、商品卡、FBO 供货单据和会计系统的一致性。

## 31. 官方页面级核验：税务问答

> 核验页面：`/libra/finances-documents/taxes/nalogi-faq`
>
> 核验日期：2026-07-30。FAQ 只作平台操作说明，税务结论以税务机关、法规和专业会计意见为准。

收入与平台角色：

- 页面说明卖家收入通常是商品销售总额，未扣除 Ozon 佣金和服务费；跨境平台收购收入还需与标准销售收入合并考虑。
- Ozon 接收买家款项并以 ООО “Интернет Решения”名义出具买家小票，但必须包含卖家信息。
- Ozon 通常作为销售代理，商品所有权由卖家直接转移给买家；特定跨境收购时 Ozon 才成为买方。
- 对 УСН“收入”口径，FAQ 明确不能从营业额中扣佣金；“收入减费用”口径才考虑佣金和 Ozon 服务费。

VAT 与单据：

- Ozon 自身服务单据中的 VAT 是 Ozon 作为 ОСНО 主体的税，不等于卖家自身需要按该税率纳税。
- 不缴 VAT 的 УСН 卖家，FAQ 指示商品卡选择“不征税”；Ozon 不因自身税制替卖家商品自动加 VAT。
- ОСНО/FBO 供货时商品卡和 УПД-2 需使用适用商品税率，并把 VAT 包含在商品价格中。
- 商品交付后跨月退货进入退货发生月份的销售报告，同时冲回买家退款、退货费并返还销售佣金。
- FBO/FBS/realFBS 不改变销售和退货的基本会计报告逻辑，但当前项目仍只实现 FBO。

折扣积分与奖金：

- 折扣积分机制本身不应造成额外重复征税。
- 未用完积分转成卢布奖金时，FAQ 要求将奖金计入收入；НПД 卖家还需在“我的税务”应用中开具相应小票。
- 奖金 VAT 处理属于高风险动态税务判断，项目只保存金额、单据和官方说明，不自动计算纳税结论。

НПД 与主体变更：

- 页面核验时 НПД 年销售超过 240 万卢布会失去该身份，不能继续以自雇身份销售。
- НПД 卖家需自行为每次商品购买在“我的税务”中开具小票；Ozon 给买家的小票不替代这一义务。
- НПД 卖家只能使用其在税务应用中登记的本人银行账户。
- 页面说明 НПД 卖家不能直接向企业买家销售，但 Ozon 可能为跨境销售收购其商品。
- 从自雇者改为个体工商户不能在原账号直接改主体，需要终止原合同/账号并用新资料注册。

项目映射：

- 保存 `gross_sales_income` 与 `platform_fees`，税务报表禁止默认用银行净到账作为收入。
- 区分 `buyer_receipt_issued_by_ozon` 与 `seller_tax_receipt_required`。
- 主体变更创建新主体和新合同，不覆写旧主体历史。
- 对 VAT、НПД 限额和税制阈值设置动态规则版本及人工复核状态。

## 32. 官方页面级核验：电子单据交换（EDI/ЭДО）

> 核验页面：`/libra/finances-documents/electronic-documents/edo`
>
> 核验日期：2026-07-30。强制使用范围、支持的运营商、连接时长和接受文件类型均可能变化。

FBO 直接价值：

- EDI 与发货条码无关，但对部分 FBO 供货和财务关账文件具有直接作用。
- 平台收购商品时需要用 EDI 签署 УПД-1 才能取得相应付款。
- FBO 可通过 EDI 发送供货 УПД-2；“Меркурий”认证商品、使用“供货前上传 УПД”的强制标记商品、珠宝及部分特定仓库/暗店供货必须使用。
- Ozon 每月关账单据也可经 EDI 接收，因此它是财务归档链的重要来源。

主体与签名：

- EDI 绑定公司 INN，不绑定单个 Ozon 后台；同一 INN 下多个后台通常只需开通一次。
- 电子文件取得法律效力需要强化合格电子签名（УКЭП）。
- 负责人或个体工商户可从俄罗斯税务机关认证中心取得法人/经营者签名；员工签署需要个人电子签名和机器可读授权书（МЧД）。
- 停用需联系 EDI 提供商；停用前必须检查是否仍有强制 УПД-2 供货，否则会影响继续供货。

连接与文件：

- 页面推荐直连运营商“Сфера Документы”和“Контур.Диадок”；直连核验时约 1–5 个工作日，其他运营商需漫游，约 5–10 天。
- 接受的结构化文件包括 УПД、УКД、发票及其更正、运单；不接受 МХ-1、ТОРГ-2。
- 接受的非结构化文件包括明细、授权书、对账单、理由异议、差异协议和证书清单；普通信件、账单、一般 акт、补充协议、合同和索赔等并非都可通过该入口发送。

项目映射：

- EDI 配置建模在法律主体层：`taxpayer_inn / provider / roaming / connected_at / signature_owner / status`。
- 每份文件保存 `edi_message_id`、发送方、接收方、签名状态、签署人/授权、原始 XML、可视化版本和回执。
- 后台下载与 EDI 收到的同一关账文件需要按文件标识和校验值去重。
- 为强制 EDI 的 FBO 商品/仓库增加供货前置校验，不能等仓库拒收后才发现缺单。

## 33. 官方页面级核验：面向企业买家销售（B2B）

> 核验页面：`/libra/finances-documents/sales-to-legal-entities/prodazhi-urlicam`
>
> 核验日期：2026-07-30。B2B 不属于当前项目优先能力，但其订单可能自然出现，导入与隔离不可缺失。

销售资格与文件模式：

- 卖家通常不能禁止企业买家购买；自雇者及适用 НПД 的个体工商户除外。
- 未开启“企业单据交换”时，Ozon 代表卖家向企业买家形成 УПД-2，买家不能凭此抵扣 VAT。
- 开启后，Ozon 代表卖家形成 УПД-1，买家可按规则申请 VAT 抵扣，卖家需单独登记企业销售并申报。
- 该选项面向缴纳 VAT 的卖家，通过后台设置开通；Ozon 形成、签署并交付文件，卖家不得重复开具同一 УПД-1。

УПД 与时点：

- 页面说明企业买家收货后通常在一天内、且不晚于发货后 3 天形成 УПД-1，并经 EDI 复制给卖家。
- УПД-1 号码需逐行登记到销售簿，交易操作代码为 01；Ozon 作为卖家授权代理，不是商品卖方。
- 买家在文件发布后 3 天内未提出异议，视为接受，通常无需另取企业买方签名。
- 若预付款与实现销售跨季度，卖家可依据企业预付款报告自行处理预付款发票。

价格、VAT 与退货：

- УПД-1 的 VAT 依赖商品卡及 FBO 标记商品供货 УПД-2 中的税率；错误需通过企业单据支持流程更正。
- УПД-1 价格可能低于商品卡价格，因为折扣差额通过积分补偿；登记销售时仍需按正式实现数据。
- 伙伴积分余额转成奖金时是另一项收入和单据事实，不应并入原 B2B 商品行。
- 企业退货、强制标记和进口商品另有单据动作；当前项目只需识别并隔离，不提供 B2B 操作台。

项目映射：

- 所有订单保留 `buyer_type`，B2B 订单关联企业 INN/KPP、УПД 状态、VAT 模式和 EDI 文件。
- 增加防重复控制：平台生成的 УПД-1 与本地外部会计单据按交易和号码比对。
- B2B 数据进入独立报表和税务导出，不混进消费者预付款或零售小票口径。
- 当前路线仅实现“识别、保存、核对和风险提示”，不建设 B2B 定价、促销、开票或退货操作能力。

## 34. 官方页面级核验：Ozon 销售佣金

> 官方页面：`/libra/commissions-tariffs/commissions-tariffs-ozon/komissii-tovary-uslugi`；核验日期：2026-08-03。类目费率、低价商品特惠、地域折扣、日期窗口和例外清单均为动态数据。

卖家向 Ozon 支付的不只是销售佣金。平台费用至少分为：按类目、商品类型和履约模式计算的销售佣金；配送、仓储等服务费；以及按买家付款方式计算的收单费。三类费用必须分别建模，不能用一个“平台抽成率”估算。

### 销售佣金确认口径

- 基数是卖家设置、含适用增值税并计入卖家承担活动/折扣后的价格，但不扣除 Ozon 以折扣积分补偿的附加折扣。
- 采用订单发生时有效的类目/类型/履约模式费率，在商品转为“已交付”时确认销售佣金。
- 退货时平台返还此前销售佣金，并冲回商品销售收入；取消或未取货不确认销售收入，也不收销售佣金。物流与退货服务费另按各自规则处理。
- 收单费按买家实际支付金额计算，费率取决于付款银行/方式；不能按卖家价或佣金基数代算。

### 类目、类型与日期版本

费率由商品类目、商品类型和 FBO/FBS/realFBS 等模式共同决定。页面费率表显示的是不含区域系数的最大佣金；没有类目/类型或技术性暂时缺失时，当前使用 10% 临时费率。项目必须保存平台实际返回的费率和分类证据，不应依赖自建类目映射猜测。

页面当前同时提供多个生效期费率表，并公告 2026-08-28 起低价商品费率调整。例如 100 卢布以内、101–300 卢布区间的 FBO/FBS 费率会按日期变化。这些数字只作为核验快照；计算必须以订单日对应费率版本为准。

### 佣金减免

- 延迟全部付款可换取销售佣金折扣，折扣与延期周期相关；这会改变现金流与费率，需单独评估资金成本。
- FBS 提前交接折扣属于非 FBO 知识边界，不进入项目操作。
- 页面公告自 2026-08-30 起部分 FBO 本地销售集群可能享受 3 个百分点佣金减免，并列出无本地库存责任、低订单样本、平台调拨、法律限制等例外。集群、日期、比例和例外都必须动态读取，不能固化。

### Ozon 出资折扣积分

Ozon 可用平台出资折扣降低买家价，并以积分补偿卖家价差。积分可抵扣销售佣金（当前最多抵扣基础佣金的 99%）及部分服务；最终可抵费用在结算期关闭后确定。若调整使基础佣金出现负值，平台可能在后续期间用更正单据调整。

### 对项目的约束

- 订单保存 `commission_base`、`commission_rate`、费率版本、生效日、类目/类型、履约模式、原佣金、减免原因、积分抵扣和最终佣金。
- 利润预估使用当前规则快照；真实利润以交付、退货、结算和更正单据事件重放，不以商品页估算替代。
- 动态费率表、低价阈值、地域折扣与延迟付款折扣均带来源 URL 和 `observed_at`；跨生效日订单不得套用今天费率。
- 本项目只采用 FBO，但保留其他模式费率用于解释历史/官方页面，不提供 FBS/realFBS 配置能力。

## 35. 官方页面级核验：FBO 配送到买家的费用

> 官方页面：`/libra/commissions-tariffs/commissions-tariffs-ozon/rashody-na-dostavku`；核验日期：2026-08-03。页面同时展示多个生效日期版本，具体金额与上限必须按订单日、商品体积和运输方向读取。

FBO 的“配送到买家”不是一个固定运费，而是至少由物流与末端交付两部分组成。物流覆盖 Ozon 仓内拣选、分拣，以及从发货仓所在集群运往买家目的集群分拨中心；末端交付覆盖从分拨链路送至提货点或买家的最后一段。销售佣金、收单费、退货费用不属于这两个项目，必须独立入账。

### FBO 物流计价结构

- 物流费取决于卖家价格、商品计费体积和实际运输方向；计费体积不是仅看重量，体积/体积重规则另由官方费率页定义。
- 发货与目的地按 Ozon 集群判断。方向能确定时使用对应集群路线费率；无法确定时可能使用按体积的通用费率。
- 如果 Ozon 没有从买家最近集群发货：当地有该商品库存时按本地费率处理；当地无库存时按最近可供货集群的方向处理。不能把平台实际调拨路径直接当作卖家的费率方向。
- 非本地销售加价只适用于发往目的集群之外的销售；本地/非本地判定要保留订单日的库存与集群证据。
- 创建 FBO 供货申请时，页面说明物流费率与供货集群通常锁定 60 天。若平台公告的新费率提前生效，锁定期可能缩短；锁定结束后使用订单日有效规则。项目需保存申请创建日、锁定截止日和公告覆盖事实。

### 末端交付

- 由合作伙伴完成末端交付时，费用按合作伙伴实际报酬计收，并受页面当期上限约束；页面核验快照显示上限为 25 卢布，但该数字不可固化。
- 由 Ozon 自有网络完成时，页面核验快照显示固定 25 卢布；同样应作为带生效日期的动态费率记录。
- 合作伙伴末端费在商品已送达提货点后发生的退货、未取货或取消中仍可能收取；在送达前取消则不应收取。
- Ozon 自营末端费在退货时可能保留，但页面说明未取货和取消不收。必须按履约事件与承运类型判断，不能仅凭最终订单状态计算。

### 对项目的约束

- 配送费用明细至少保存 `fee_type`、`fulfillment_scheme`、`chargeable_volume`、发货/目的集群、计价方向、本地销售标记、承运类型、费率版本、订单日和实际金额。
- 供货申请保存费率锁定版本与截止日；利润预测按锁定规则估算，结算以平台财务交易为准。
- 订单必须保留“到达提货点、交付、拒收、取消”的事件时间线，末端费不能由单一 `status` 反推。
- 当前项目只实现 FBO；FBO Fresh、FBS 和 realFBS 费率仅作为历史解释知识保留。

## 36. 官方页面级核验：退货、未取货与取消费用

> 官方页面：`/libra/commissions-tariffs/commissions-tariffs-ozon/rashody-na-otmenu-vozvraty`；核验日期：2026-08-03。页面按履约模式折叠显示具体费率，金额仍需按事件日的官方费率版本和财务交易核对。

官方以买家是否已经取得商品来区分三类业务事件：

- **退货（возврат）**：商品曾进入“已交付”，已经产生销售收入、销售佣金、收单费和正向配送费，之后买家再退回。
- **未取货/部分拒收（невыкуп）**：买家收货时拒绝部分商品；接受的商品进入“已交付”，拒收商品进入“已取消”并返仓或等待退还卖家。
- **取消或无人领取（отмена / невостреб）**：整票未被买家取得，进入“已取消”，随后返仓或等待移交卖家。

这三类事件会导致完全不同的销售和费用冲回。已交付后退货需要冲回销售收入并返还销售佣金；未取货与取消本来就不确认销售收入和销售佣金，但正向、反向物流及处理服务仍需按实际节点判断。

### 60 天未完成返程的保护规则

从 Ozon 收到买家退货/未取货，或收到取消信号起超过 60 天，如果货件仍未：

- 送达退货集群内的仓库；
- 在接收点等待卖家领取；
- 由快递退回卖家；

页面说明不应收取货件处理、物流、送至交付地点、反向物流，以及退货/未取货/取消/无人领取处理费。项目应建立 60 天时钟，并用财务交易反查异常扣费，而不是假定平台一定自动纠正。

### Ozon 责任与收单费例外

- 因 Ozon 责任造成取消或退货时，卖家不承担相关费用，平台负责返仓或准备移交；需要保存责任方/原因码作为申诉与对账证据。
- 收单费通常随退款处理，但并非保证全部返还。如果买家退款进入 Ozon 账户余额而非原银行卡，收单银行没有登记银行卡退款，平台可能无法返还收单费。
- 若收单银行与 Ozon 的合同约定收单费不可退，也不会返还。项目不得用“退款成功”自动推导“收单费已返还”。

### 对项目的约束

- 建立独立事件类型 `return_after_delivery`、`partial_refusal`、`full_cancellation`、`unclaimed`，不要把它们都压成 `returned`。
- 保存最初取消/退货信号、进入退货集群、等待领取、实际返仓/返卖家的时间；计算 `return_age_days` 并预警超过 60 天仍扣费的交易。
- 每个商品行分别重放销售收入、销售佣金、收单费、正向物流、末端交付、反向物流和处理费；部分拒收不可整单冲回。
- 保存 Ozon 责任标记、买家退款渠道、收单费返还交易和更正单据，形成可审核的申诉证据链。

## 38. 跨境销售与境外供应：交易类型必须先识别

> Ozon 大学入口：`/libra/prodaji-i-postavki-v-drugie-strany`；相关费用入口：`/libra/commissions-tariffs/commissions-tariffs-ozon/vykup-tovarov-pri-prodaje-v-drugie-strany`。
>
> 官方历史公告：[Ozon Marketplace 官方频道](https://t.me/s/ozonmarketplace)，2024-12-04 发布“境外订单计入本地化指数”的更新；核验日期：2026-08-03。公告中的国家资格、税制、日期、费率、免费期和仓点均为历史动态事实，实际跨境业务必须核对当前合同、知识库和法规。

跨境不能只用 `buyer_country != seller_country` 判断。官方公告显示，俄罗斯卖家的境外订单至少可能出现：

1. **从俄罗斯库存直接发往境外买家**；
2. **Ozon 先收购商品，再完成境外销售**；
3. **卖家把商品供应到买家所在国家的仓库，从当地库存销售**。

这三类交易在商品所有权转移、销售对手方、发票/УПД、税务、清关、库存仓属、结算和本地化指标上不同。项目必须先识别交易类型，再入账，不能把它们统一记作普通俄罗斯境内零售。

### 跨境事实模型

订单/交易至少保存：

- 卖家法律主体、合同实体、买家/平台收购方及各自国家；
- `cross_border_mode`：直发、平台收购、境外本地库存销售；
- 商品所有权转移时间和证据单据；
- 订单币种、结算币种、原币金额、换算汇率、汇率日期和舍入；
- 出口/进口申报、TN VED、原产国、强制标记、证书及限制状态；
- 发货国、仓库国、买家国、运输路线和海关事件；
- 销售收入、平台收购收入、佣金、物流、税费、关税和更正分别入账。

### 境外 FBO 供应

官方 2024 公告当时允许部分卖家向哈萨克斯坦和白俄罗斯仓库供应，并提到可从俄罗斯接收点使用跨仓服务；具体资格与文件依税制/EDI 等条件而不同。稳定的项目结论是：

- 境外仓是独立仓库/集群主数据，库存、供应申请、仓点资格和费用不得并入俄罗斯仓；
- 供货前按目的国检查禁限售、认证、标记、海关和税务要求；俄罗斯商品卡可售不代表目的国可入仓/可售；
- 供应申请保存起运国、目的国、边境/海关节点、承运责任和单据包；
- 本地化指数及其折扣是动态运营规则，不参与法律上的交易类型判断。

### 项目采用边界

- 当前 ozon-workbench 不提供跨境供货、清关、税务申报或境外仓操作能力；只识别和隔离可能出现的跨境订单/单据。
- 若同步到平台收购单据，必须与代理零售报告去重，避免同一商品重复确认收入。
- 汇率、VAT/间接税、出口零税率、EAEU 报告和海关责任必须由当前官方文件及专业会计/报关判断，Skill 不给静态税务结论。
- 所有国家资格、商品例外和费率保存 `effective_from/to`、来源与核验时间。

## 39. 金融服务：付款加速、信贷与应收融资分开建模

> Ozon 大学入口：`/libra/fintech`。
>
> 当前官方来源：[Ozon 银行企业服务](https://finance.ozon.ru/business)、[商城卖家经营贷款](https://finance.ozon.ru/business/credit/seller)、[供应商保理](https://finance.ozon.ru/business/factoring/classic)；合同来源：[金融服务合同更新](https://seller.ozon.ru/media/news/o-finansovyh-uslugah-novoe-v-dogovore/)。核验日期：2026-08-03。额度、利率、期限、资格、放款速度和产品名称均为动态营销/合同数据，实际决策以个别报价和签署合同为准。

当前官方企业金融入口同时展示结算账户、每日付款账户、灵活付款、经营贷款、采购融资、销售前融资、保理、收单等产品。它们的经济实质不同：

| 类型 | 核心事实 | 不可混淆 |
|---|---|---|
| 结算/每日付款账户 | 银行账户、余额、利息、转账与服务费 | 平台销售结算不等于银行到账 |
| 提前/每日/每周付款 | 把平台应付卖家的时间提前或改变频率并收取服务费 | 不是销售收入增加，也不一定是贷款 |
| 经营贷款 | 银行/贷款方给付本金，卖家按合同偿还本金和费用 | 放款不是收入；还本不是费用 |
| 采购融资 | 资金可能直接支付给供应商并形成可循环限额 | 不是已完成采购或 FBO 已入仓 |
| 销售前融资 | 以库存/预计销售等为基础提前取得资金 | 预计销售不是已实现销售 |
| 保理 | 以真实应收和供货为基础，将应收融资或转让给保理方 | 与普通贷款、商城代理销售分开 |
| 收单 | 为外部渠道收款并形成交易/退款/手续费 | 与 Ozon 商城买家付款和平台收单费分开 |

### 贷款状态与证据

建议状态机：

`offer_seen → application_started → documents_submitted → scored → offered → contract_signed → disbursed → active → repaid / overdue / restructured / closed`

每份融资保存：产品、法律提供方、借款主体、合同和版本、申请/批准额度、实际本金、币种、费率表达方式、总成本、期限、付款计划、担保/抵押、提前还款和违约条款。营销页当前展示的最高额度、期限和最低月费率仅作观察快照，不能替代卖家的个别合同。

官方贷款页说明平台/其他市场销售统计及银行流水可能用于自动评估；这属于敏感经营数据。项目只能在明确授权下导入，记录提供范围、目的、时间和撤销/删除要求，不能静默上传全量财务数据。

### 现金流和账户限制

- 销售、平台应付、付款计划、平台发起、银行处理中和银行到账分别记录。
- 2025 合同公告说明付款可能在计划日后继续由银行处理，并明确特定 Ozon 银行贷款有效时收款账户受合同约束；这是账户变更前必须检查的风险。
- 融资放款进入现金流表但不进入利润；利息、服务费和保理折价按合同和会计口径确认。
- 自动扣款保存计划日、应付额、实际扣款、资金不足、逾期、罚息/费用和更正；不能用余额下降反推本金/利息分拆。

### 决策检查

任何融资建议至少比较：

- 融资前后现金缺口和安全库存；
- 全部资金成本，而非只看“每月起”费率；
- 销售下行情景、退货、广告回收期和库存周转；
- 还款与 Ozon 结算日期错配；
- 收款账户绑定、数据授权、担保与提前还款限制。

项目可以做情景分析和到期提醒，但不得自动申请、接受报价、签署合同、上传敏感材料、变更收款账户或发起还款。金融产品默认属于高风险人工操作。
