# Performance API

Ozon 官方 `performance API` 是推广 / 投放 / campaign 管理接口族，不是商品、FBO 或财务主链路。

## 已确认的章节级结构

- `ListCampaigns`：campaign 总览 / 列表
- `ActivateCampaign`：激活动作

这说明该 API 分支至少包含两类能力：

1. 看活动
2. 改活动

## 方法族而不是单页

这条 API 分支更适合按“方法族”理解，而不是按单个页面记忆。当前已经能稳定分出的方法族有：

- 列表 / 查询方法：先看 campaign 有哪些、处于什么状态
- 动作 / 修改方法：激活、暂停、改预算、改出价、改策略、加删商品、关闭活动
- 结果归档方法：记录执行时间、状态变化、返回结果和最终生效
- 变更历史方法：记录 campaign 改了什么、什么时候改、由谁改、是否已生效

对 skill 来说，最重要的不是背每个页面标题，而是先判断：

1. 这是读方法还是写方法
2. 这是列表层还是单对象层
3. 这是即时生效还是异步受理
4. 这是配置动作、结果归档还是变更历史

## 对应的业务范围

- campaign 列表与状态
- campaign 激活 / 暂停
- 预算与出价
- 商品加入 / 移除活动
- 外部平台对接
- 结果归档与版本记录
- 变更历史与审计

## 官方帮助页已经明确的 campaign 动作

从官方帮助页可以确认，这条 campaign 线至少包括这些可操作项：

- 修改 campaign 预算
- 修改预算自动上调比例
- 修改出价
- 修改出价策略
- 添加商品
- 删除商品
- 关闭 campaign

这说明 performance API 不只是“看投放”，它也覆盖投放动作本身的编辑和停用。

## 这章应如何在 skill 里使用

当用户问到 performance API 时，优先按下面顺序回答：

1. 这是 campaign 分支，不是商品 / FBO / 财务主链路。
2. 先区分列表层、动作层和结果归档层。
3. 再看是预算、出价、策略、商品，还是关闭活动。
4. 最后才讨论自动化或项目接入。

## 列表层应关注的结构

`ListCampaigns` 这类接口通常要先看：

- 是否支持分页
- 是否支持状态筛选
- 是否支持按名称、类型、时间过滤
- 返回的是全量还是子集

## 动作层应关注的结构

`ActivateCampaign` 这类接口通常要区分：

- 请求成功
- 已受理
- 最终生效
- 是否存在异步完成

## 与项目的关系

这个分支应单独归到推广章节，而不是主 Seller API。
对 `ozon-workbench` 最有用的是：

- 先把 campaign 状态列出来
- 再做版本归档
- 再做预算 / 出价 / 商品配置变化的识别
- 最后才考虑自动化执行

## 关键不要混淆

- 推广 API 不是商品 API
- 激活动作不是查询动作
- 返回值不是 ROI
- 动作结果不是经营结果
- 历史变更不是当前状态
